=== Décisions architecturales (cadrage S-076)

. *Boundary* : codex = implémenteur privé du contrat MEMPHIS. Le contrat
  est OSS (Apache 2.0), l'implémentation du pont RAG est OSS (codex Apache 2.0).
  Pas de code propriétaire ici — la frontière licence 3 étages place
  l'orchestration agentique privée dans workspace-gradle, pas dans codex.
. *Table dédiée* `codex_learner_profiles` — séparée de `codex_documents`/
  `codex_chunks`. Rationale : le profil n'est PAS un document du corpus,
  c'est de la mémoire de session. Mélanger les deux casserait la recherche
  sémantique (un Retrieve sur un module pédagogique retournerait le profil
  du stagiaire — bruit). Clé composite `(learner_id, formation_id)`.
. *Embedding profil* : concaténation `weakPoints.joinToString` +
  `annotations.values.joinToString`. Pas d'embedding sur `completedModules`
  (liste de IDs, pas sémantique). Pas d'embedding sur `progressionPct`/
  `comprehensionScore` (numériques, filtrage SQL direct).
. *Domaine* : `codex.profile` (12e domaine codex — voir codebase.agents
  ontologique). Mirror pattern `codex.ocr` (port + adapter + config).
. *Non-regression* : zéro impact sur le pipeline documentaire existant.
  Nouvelle table, nouveau domaine, nouvelle tâche. Backward compat total.
. *Gate MEMPHIS* : ne pas démarrer l'implémentation tant que
  `runtime-contracts:0.0.1` n'est pas publié sur Maven Central
  (EPIC-RC-07). Pour progresser : ouvrir une session MEMPHIS dédiée à
  RUNTIME-CONTRACTS-1..7 (publication préalable).

=== Prochaine action

*Côté MEMPHIS* : démarrer EPIC RUNTIME-CONTRACTS (US RC-1..7) dans une
session MEMPHIS dédiée. Publier `runtime-contracts:0.0.1`.
*Côté codex* : dès publication MEMPHIS, bump codex build.gradle.kts
