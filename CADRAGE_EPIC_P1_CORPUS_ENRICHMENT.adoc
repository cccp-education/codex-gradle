== Contexte — P1 Enrichissement Croisé du Corpus

La section `[[p1-codex-enrichment]]` du `PLAN_GLOBAL.adoc` définit 5 EPICs
P1 pour codex-gradle (Brooklyn N2) :

 * *CDX-3 (ontologie) — `deriveOntology`* (P1-19) — SQL LMD → cartographie
   ontologique. Bounded contexts, agrégats, value objects *calculés*.
 * *CDX-4 (ontologie) — `enrichJsonLdd`* (P1-20) — Croisement JSON LDD + RAG
   pgvector + Knowledge Graph Graphify.
 * *CDX-5 (codex) — `exportKnowledgeBase`* (P1-21) — JSON-L / Markdown /
   AsciiDoc vers `office/` ou `OSS/` selon licence.
 * *CDX-6 — Intégration OSS/CSS + routing licence* (P1-22) — PDF Apache/CC →
   `OSS/`, PDF copyright → `office/`.
 * *CDX-7 — Tests unitaires + intégration* (P1-23) — ExtractTextTask,
   TypographicAnalyzer, MarkdownConverter, SemanticChunker + test
   intégration sur PDF canonique.

Aucun de ces EPICs n'était présent dans l'INDEX/BACKLOG codex. Cette session
cadre les 5 en baby-step DDD/TDD/BDD, zéro code modifié (gouvernance pure).

== Décisions architecturales (cadrage S-077)

. *Domaine `codex.ontology`* (nouveau, 12e — voir `codex.ocr` 11e, `codex.profile` 13e gated MEMPHIS). Contient les types ontologiques purs : `BoundedContext`, `Aggregate`, `ValueObject`, `OntologyMapping`. Mirror pattern `codex.ocr` (port + adapter + config).

. *`deriveOntology` est un object pur* (pattern `OcrPipeline`/`LicenseZoneDetector`). Entrée : `List<LddNode>` (JSON LDD existant). Sortie : `OntologyMapping` (data class immutable). Pas de tâche Gradle dédiée initialement — c'est une étape du pipeline enrichi. Tâche `deriveOntology` (groupe `transform`) ajoutée si besoin standalone.

. *3 requêtes archétypales SQL* (P1-19 spec) — `deriveOntology` analyse le SQL LMD généré par `ImportBookSqlTask` + le JSON LDD pour *calculer* (pas deviner) :
 ** Bounded contexts → groupements de tables liées par FK.
 ** Agrégats → tables racines avec leurs entités dépendantes (CASCADE).
 ** Value objects → tables sans FK sortantes + colonnes immutables.

. *Domaine `codex.enrichment`* (nouveau, 13e) pour CDX-4. Contient `JsonLddEnricher` (object pur) + `GraphifyResolver` (port) + `GraphifyFileResolver` (adapter lit `graph.json`). Pas de dépendance compile `graphify-gradle` — consommation par fichier `graph.json` (contrat N0, pas de couplage Gradle).

. *`enrichJsonLdd` enrichit chaque `LddNode`* avec :
 ** `ragChunks: List<DocumentChunk>` — chunks RAG joints par `sectionPath` (requête pgvector par section title).
 ** `graphifyNodes: List<String>` — nœuds Graphify résolus par titre de section (match label → node id).
 ** `semanticDensity: Double` — ratio `ragChunks.size / totalChunks` pour la section.
 ** `entities: List<String>` — entités extraites du contenu (peuple `DocumentChunk.entities` placeholder).

. *Domaine `codex.licence`* (nouveau, 14e) pour CDX-5/CDX-6. Extrait `LicenseZoneDetector` (existant) + ajoute `PdfLicenseDetector` (détecte licence du *contenu* PDF, pas du projet). `LicenseRouter` route la sortie vers `OSS/` ou `office/` selon licence détectée. Backward compat : `LicenseZoneDetector` inchangé (détection par chemin projet), `PdfLicenseDetector` est additive.

. *`exportKnowledgeBase` étendu* — `ExportKnowledgeBaseTask` existant inchangé (output `build/codex/knowledge-base/`). Nouvelle tâche `deployKnowledgeBaseRouted` (groupe `deploy`) qui route vers `office/knowledge-base/` ou `OSS/knowledge-base/` selon `PdfLicenseDetector`. Backward compat total.

. *CDX-6 routing licence* — `PdfLicenseDetector` scanne le PDF source pour :
 ** Mention "Apache License 2.0" / "Apache-2.0" → OSS.
 ** Mention "Creative Commons" / "CC-BY" / "CC0" → OSS.
 ** Mention "©" / "Copyright" / "All rights reserved" → CSS (office/).
 ** Aucune mention → fallback `LicenseZoneDetector.detect(projectDir)` (comportement actuel).

. *CDX-7 tests* — 3 niveaux baby-step TDD/BDD :
 ** Unit : `FontStyleDetectorTest`, `PdfLicenseDetectorTest`, `OntologyMappingTest`, `JsonLddEnricherTest`, `GraphifyFileResolverTest` (fakes, pas d'I/O).
 ** Functional : `DeriveOntologyTaskTest`, `EnrichJsonLddTaskTest`, `DeployKnowledgeBaseRoutedTaskTest` (tasks Gradle réelles, ProjectBuilder).
 ** Integration : `CodexPipelineIntegrationTest` — PDF canonique de `office/books-collection/` → pipeline complet → assertions sur chunks + ontology + enrichissement.

. *Gate MEMPHIS* : CDX-4 `enrichJsonLdd` peut câbler le canal Graphify (`graphifySection`) sans bump BOM — `CompositeContextConfig` N0 (codebase-contracts 0.0.2) déjà en classpath. Pas de gate.

. *Non-regression* : zéro impact sur le pipeline documentaire existant. Nouveaux domaines, nouvelles tâches, backward compat total. `LicenseZoneDetector` inchangé. `ExportKnowledgeBaseTask` inchangé.

. *Zéro bump BOM* : tous les types N0 nécessaires (`ContextChannel`, `CompositeContext`, `CompositeContextConfig`, `ChannelBudget`) sont déjà publiés dans `codebase-contracts:0.0.2` (classpath codex).

. *English only* — code, identifiants, commentaires, tests, features Gherkin (règle AGENTS.adoc).

. *Méthode* : baby-step DDD/TDD/BDD strict (RED → GREEN → REFACTOR), 3 niveaux de tests (unit → functional → cucumber). Pattern S-057/S-063 pour le cadrage (gouvernance pure, zéro code).
