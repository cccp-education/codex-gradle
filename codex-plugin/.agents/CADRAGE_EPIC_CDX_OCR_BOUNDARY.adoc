== Contexte — La règle du pilote

Le pilote a tranché (session 096) :

* *OCR logiciel* (Tesseract, mécanique) → *codex* (Brooklyn N2) l'actionne.
* *OCR assisté IA* (vision LLM) → *codebase* (Queens N1) l'actionne.

Cette répartition n'était pas formalisée dans la gouvernance. L'état du code
la viole des deux côtés. Ce document cadre l'EPIC de remise en boundary.

== Décisions architecturales (cadrage S-096)

. *EPIC cross-borough* Brooklyn (codex) + Queens (codebase). Priorité P1 —
la frontière licence/métier et la cohérence du DAG en dépendent.

. *codex GARDE* (son métier READ — acquisition documentaire) :
 `OcrRequest`/`OcrResult`/`OcrConfig` (types purs), `TesseractOcrEngine`
 (software OCR — LA règle), `DiskCacheStorage`/`OcrResultCache` (économie
 d'encre), `CollectOcrTask` + contrat pages N2↔N2 (`NNN-<pageId>.adoc`),
 orchestration `OcrPipeline` (fallback AI→software).

. *codex RETIRE* : `LlmOcrEngine`, `HttpOllamaChatClient`, `OllamaChatClient`.
 `OllamaProbe` est *conservé* (utilitaire de test `assumeTrue`, plage
 11437-11465 — pas un moteur IA).

. *Port d'injection* : PAS de nouveau type. `codex.ocr.OcrEngine` (fun
 interface existante) EST le port. `OcrPipeline` reçoit l'engine IA par
 injection ; défaut sans injection = Tesseract seul (dégradé fonctionnel,
 backward compat).

. *Adapter `VisionOcrEngineAdapter : codex.ocr.OcrEngine` vit côté codebase*
 — wrappe `VisionProvider` (IA) derrière le port codex. Zéro circularité :
 codebase a déjà `libs.codex.plugin` (constat #2). Sens unique : N1 offre,
 le consommateur câble.

. *Zéro nouvelle dépendance codex→codebase* — un `implementation(libs.codebase.plugin)`
 créerait un CYCLE N2↔N1 interdit. Le wiring se fait au composition root
 (consommateur : training/runner/tests) ou en test (fake).

. *Suppression `CodexOcrEngineAdapter`* (codebase) — sens inverse de la
 boundary (exposait le software comme VisionProvider). `CodebaseOcrExtension`
/`OcrTask` deviennent IA-uniquement (Gemini/Ollama via `VisionProvider`) ;
 plus d'import `TesseractOcrEngine`.

. *Split-brain `CodexVectorStore` HORS SCOPE* — 5 fichiers koog codebase
 utilisent `codex.store.CodexVectorStore` (CompositeContextBuilder,
 CodebaseCompositeContextTask, KoogAugmentedContextGraph,
 MultiChannelContextGraph, KoogPlanningOrchestrator). L'inversion N1→N2
 dépasse l'OCR. EPIC futur dédié (cadrage séparé requis).

. *Parité comportementale* : avant toute suppression, characterization tests
 verrouillent la sortie AsciiDoc structuré de la chaîne actuelle. La qualité
 OCR IA doit être équivalente via les providers codebase.

. *Non-régression* : `collectOcr` sans provider IA câblé → Tesseract seul
 (fonctionnel). Avec adapter câblé → même chaîne qu'aujourd'hui. Contrat
 pages inchangé. Cache hash inchangé.

. *English only* — code, commentaires, Gherkin (règle transverse).

. *Méthode* : baby-step DDD/TDD/BDD strict RED → GREEN → REFACTOR,
 3 niveaux (unit → functional → Cucumber).

== Gates et risques

* *Cycle N2↔N1* : interdit formel — d'où la décision 6 (adapter côté codebase).
* *Qualité OCR IA* : les prompts de `LlmOcrEngine` sont perdus à la
 suppression ; si la parité n'est pas atteinte via `VisionProvider`,
 porter le prompt canonique dans le provider codebase (décision à acter
 en US-2 si constaté).
* *Consommateurs actuels de `collectOcr`* : flux Tombouctou FPA (livre
 scanné) — vérifier le wiring chez le consommateur après purge (US-3).
