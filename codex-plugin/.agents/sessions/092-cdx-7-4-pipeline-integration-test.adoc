== Réalisation

*CDX-7-4 TERMINÉ* — `CodexPipelineIntegrationTest` (3 tests
`@Tag("integration")`) chaîne les 3 tâches du pipeline sur un PDF
canonique réel (`office/books-collection/litterature/Manifeste des 60.pdf`,
65 KB — le plus petit livre réel du corpus) :

. `ExtractBookStructureTask` — PDF → AsciiDoc (détection typographique)
. `ConvertToMarkdownTask` — AsciiDoc → Markdown
. `ChunkDocumentTask` — Markdown → chunks JSON sémantiques

*Skip propre* via `assumeTrue(pdfFile.exists())` quand le corpus est
absent (CI sans books, fresh clone). Résolution du PDF canonique
robuste : walk-up depuis le working dir jusqu'au workspace root,
fallback system property `codex.canonical.pdf`.

*3 tests* :
. `full pipeline on canonical PDF produces non-empty chunks` —
  validate que le pipeline complet produit un fichier chunks JSON
  non vide.
. `full pipeline chunks have deterministic SHA-256 ids` — chaque
  chunk id matche `chk-[0-9a-f]{16}`, sourceDocument = stem du PDF.
. `full pipeline chunks preserve extracted heading content` —
  sectionPath non null, headingLevel 1..6, content non-blank.

*Résultat local* : 87 chunks produits (126 total lines), 303 lignes
Markdown, 21072 bytes. Pipeline complet vert sur livre réel.

*Baby-step TDD strict* : RED (tests skippés car PDF non résolu —
