== Mission

US-3/4 de l'EPIC CDX-OCR-BOUNDARY (cadrage S-096). Après CDX-OCR-1
(port `OcrEngine` injectable, S-098) et CDX-OCR-2 (adapter
`VisionOcrEngineAdapter` côté codebase + `OcrTask` IA-uniquement,
S-099), la pile OCR IA de codex n'avait plus de raison d'exister :

. `LlmOcrEngine` — moteur OCR LLM (Ollama vision)
. `HttpOllamaChatClient` — client HTTP Ollama `/api/chat`
. `OllamaChatClient` — port du client HTTP
. `OcrConfig` — configuration provider/model (consommée uniquement par
  la pile IA)
. Props `ollamaHost`/`ollamaPort`/`model` inertes sur `CollectOcrTask`
  (marquées inertes depuis CDX-OCR-1, conservées backward compat)
. Conventions `ollamaHost`/`ollamaPort`/`ollamaModel` sur `CodexExtension`

`OllamaProbe` est CONSERVÉ (utilitaire de tests d'intégration, plage
11437-11465, aucun couplage avec la pile IA purgée).

== Constat pré-purge

. `OcrConfig` n'était plus consommée que par `LlmOcrEngine`/
  `HttpOllamaChatClient`/`OllamaChatClient` — zéro usage dans le code
  de production hors pile IA.
. `TesseractOcrEngine` ne dépendait pas de `OcrConfig` (config locale
  propre via `tesseractPath`).
. `CollectOcrTask` ne référençait plus les props ollama dans
  l'action (depuis S-098) — juste les propriétés Gradle inertes.
. `OcrPipeline` consomme `OcrEngine` (port fun interface) — zéro
  couplage avec `OllamaChatClient`/`OcrConfig`.
