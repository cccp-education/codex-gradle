== Leçons

. *Le DAG publication est une chaîne de gardes, pas une procédure* : chaque
   bump est d'abord rendu RED par sa garde (`PlatformCatalogAlignmentTest`,
   `CodexPluginPublicationTest`), puis GREEN par le bump. Le baby-step TDD
   s'applique aussi à la gouvernance de version.
. *Pin multi-site* : un bump MEMPHIS touche 3 fichiers côté codex (toml
   local, pin settings catalog, pin platform BOM) — la garde #2 les couvre
   tous.
. *Anti-collision systématique* : repo1 interrogé *avant* chaque
   `publishAggregationToCentralPortal` (piège #6, nmcp mordu S-215).
