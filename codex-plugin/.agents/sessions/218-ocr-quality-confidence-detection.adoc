== OCR-QUALITY-1 — vraie confidence Tesseract

=== BS-1 — `TesseractTsvParser` objet pur (7 UT)

Tesseract est invoqué avec le config `tsv` en plus du `txt` ; `output.tsv`
expose une colonne `conf` par mot (0..100, `-1` pour les lignes
conteneurs). Le parser produit la moyenne des mots, normalisée dans [0,1].

Règles d'honnêteté du signal (Loi de l'Économie d'Encre — le doute ne doit
pas être masqué) :

* seules les lignes `level == 5` (mots) sont comptées ;
* confiance négative (conteneur/non fiable) ignorée ;
* *texte blanc ignoré* — une image bruitée émet des « mots » espaces à
  haute confiance ; les compter masquerait précisément le doute à
  détecter ;
* lignes malformées ignorées silencieusement (best-effort, jamais ne jette) ;
* TSV vide/sans mot → confiance 0.0.

RED (7 `Unresolved reference 'TesseractTsvParser'`) → GREEN 7/7.

=== BS-2 — `TesseractOcrEngine` vraie confidence

`ProcessBuilder(tesseract, input, outBase, "-l", lang, "txt", "tsv")`.
`confidenceSource` ajouté aux metadata : `"tsv"` (mesure réelle) ou
`"degraded"` (TSV absent — vieux build Tesseract ; le texte est préservé,
zéro score simulé). Tests :

* unit + fonctionnel (image PNG rendue via AWT `BufferedImage`/`ImageIO`,
  sans outil externe) : image propre → `confidence > 0.5`,
  `confidenceSource == "tsv"` ;
* image sans mot → confiance 0.0 (signal de doute) ;
* stub tesseract sans TSV → texte préservé + `confidenceSource ==
  "degraded"`.

*Découverte en RED (régression potentielle réelle)* : l'ancien gate de
`OcrPipeline` (`confidence > 0.0`) aurait jeté le texte d'un moteur
dégradé (texte réel, confiance 0). `OcrPipeline.process` ne gate plus que
sur le texte non vide — la confiance devient un *signal de doute aval*,
jamais un critère de fallback. Test de verrouillage ajouté
(`OcrPipeline keeps text from a degraded engine even at zero confidence`).

RED (2 FAIL) → GREEN → REFACTOR.

== OCR-QUALITY-2 — détection images problématiques à l'acquisition

=== BS-1 — `OcrQualityAnalyzer` objet pur (11 UT)

`OcrQualityReason` (ILLISIBLE / TOO_SHORT / LOW_CONFIDENCE / IMAGE_MISSING)
+ `OcrQualityIssue(pageId, imageFile, reason, detail)` + `OcrQualityReport`
(`@Serializable`, `issueCountByReason()`).

Ordre des règles (mirror document-side, OCR-QUALITY-3) : raisons
whole-page *exclusive-first* (ILLISIBLE, TOO_SHORT) puis raisons
structurées cumulatives (LOW_CONFIDENCE, IMAGE_MISSING). Une page peut
porter plusieurs issues. Regex `image::?` couvre la macro bloc ET inline
(le corpus réel utilise la forme inline — piège découvert document S-252).
