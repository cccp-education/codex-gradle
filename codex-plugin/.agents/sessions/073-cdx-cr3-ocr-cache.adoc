== EPIC CDX-CR3 — Revue CR-GLOBALE-003 (3/3 US TERMINÉ)

=== CDX-CR3-1 — SQL injection `CodexIngestTask.kt:118` (🔴 P0)

*Constat* : `UPDATE codex_chunks SET embedding = '[$vec]'::vector WHERE id = $chunkId`
interpolait `$chunkId` (Long) et `$vec` (String) directement dans le SQL.

*Fix* : extraction des templates SQL dans `IngestStatements` (objet pur, domaine
`codex.store`). Les templates `insertDocument`/`insertChunk` utilisent les
paramètres positionnels `$1, $2...` (R2DBC bind). Pour `updateEmbedding`, le
vecteur reste inliné comme littéral SQL safe (nombres ONNX, jamais d'entrée
utilisateur) car pgvector n'expose pas de cast implicite `text → vector` dans
un contexte `SET` — limitation R2DBC PostgreSQL documentée. Le `chunkId` (Long
généré par `RETURNING id`) est safe à inliner.

*Tests* : `IngestStatementsTest` (10 unit) — valide les paramètres positionnels,
l'absence d'interpolation Kotlin, les compteurs de binds.

=== CDX-CR3-2 — `CodexCompositeContextTask` hardcode `localhost:5432` (🔴 P0)

*Constat* : `CodexCompositeContextTask.kt:39` instançait `CodexVectorStore()` sans
argument → defaults `localhost:5432/codex/codex/codex`. La task n'exposait aucune
propriété pg — inutilisable hors localhost. Le plugin ne wire pas l'extension
`codex { pgvectorHost = ... }` dans cette task (contrairement à `collectIngest`
et `collectRetrieve`).

*Fix* : exposition de 5 propriétés `pgHost/pgPort/pgDatabase/pgUser/pgPassword`
(annotées `@Input`) sur la task, avec conventions backward compat
(localhost:5432/codex/codex/codex). `CodexVectorStore` instancié avec les
valeurs de l'extension. Plugin wiring depuis `CodexExtension`.

*Tests* : `CodexCompositeContextTaskTest` (7 unit) — valide l'exposition des
propriétés, la configurabilité, les defaults backward compat.

=== CDX-CR3-3 — `chunk_index` incorrect pour contenu dupliqué (🟠 P1)

*Constat* : `CodexIngestTask.kt:110` utilisait `chunks.indexOf(chunk)` sur la
liste globale. Pour deux chunks identiques (même contenu, même sectionPath),
`indexOf` retourne la première occurrence → même `chunk_index` en base,
corrompant l'ordre de lecture du corpus.

*Fix* : compteur local par document (`docChunks.withIndex()`) au lieu de
`chunks.indexOf(chunk)`. Extraction de la logique dans `IngestIndexing`
(objet pur, domaine `codex.store`).

*Tests* : `ChunkIndexAssignmentTest` (6 unit) — valide les index séquentiels,
les duplicatas, la localité par document.

== US-CDX-13-1 — Persistance OcrResult par page (cache disque hash image)

*Loi de l'Économie d'Encre* (Regle 5 AGENT.adoc) : ne pas re-OCRoiser une
image dont le hash n'a pas changé.

*Implémentation* :
- `OcrResultCache` (domaine `codex.ocr`) — objet pur, cache par hash SHA-256
  de l'image source. Délègue les I/O au `CacheStorage` (port injectable).
- `DiskCacheStorage` — implémentation disque (JSON `<pageId>.ocr-cache.json`).
- `CollectOcrTask` — propriété `cacheDir` optionnelle. Cache hit → skip LLM,
  réutilisation du résultat stocké. Cache miss → appel pipeline + store.
- Dégradé silencieux : erreur stockage → miss (pas de crash).

*Tests* : `OcrResultCacheTest` (13 unit) — cache hit/miss, hash mismatch,
pageId mismatch, overwrite, dégradé silencieux, `isReusable`.
