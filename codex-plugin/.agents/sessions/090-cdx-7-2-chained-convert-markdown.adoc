== B. Constats pré-implémentation

. `ConvertToMarkdownTask.convert()` consomme un fichier AsciiDoc
  (`adocFile: RegularFileProperty`) et produit un Markdown
  (`markdownFile: RegularFileProperty`) — conversion ligne par ligne
  déterministe (headings, code blocks, admonitions, tables, images,
  links, lists, inline).
. `ExtractBookStructureTask.extract()` consomme un PDF (`pdfFile`) et
  produit un AsciiDoc (`outputFile`) — extraction PDFBox + analyse
  typographique (FontStyleDetector + TypographicAnalyzer) → headings
  `=/==/===/====`, code blocks `[source,text]` + `----`, inline code
  `` `single_line_code` ``.
. *Chaining* : `outputFile` (AsciiDoc) → `adocFile` (AsciiDoc). Les deux
  sont `RegularFileProperty` → `task.adocFile.set(extractTask.outputFile.asFile.get())`.
. Aucun test chaîné existant — tous les tests instantiate une seule
  tâche via `ProjectBuilder` en isolation.
. `ExtractBookStructureTaskTest.createSyntheticPdf` (lignes 222-288)
  fournit le pattern de PDF synthétique réutilisable (bold 20pt titre,
  bold 16pt section, normal 11pt body, bold 14pt sous-section, mono
  10pt code).
. Sortie réelle observée sur le PDF synthétique (scratch test jetable) :
  AsciiDoc `= Introduction to Programming` / `== Getting Started` /
  `==== Hello World Example` + code block `function main() { ... }` →
  Markdown `# Introduction to Programming` / `### Getting Started` /
  `#### Hello World Example` + code lines préservées.
. *Note* : le code block extrait n'a pas les `----` fermants sur une
  nouvelle ligne (le groupe mono suivant est collé), donc le
  convertisseur ne flush pas en code fence ``` ``` ``` — il préserve
  néanmoins les lignes de code comme texte. Ce comportement est
  *caractérisé* tel quel (characterization test GREEN), pas corrigé —
  CDX-7-2 est un test suite, pas un fix.
