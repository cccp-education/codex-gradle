=== Cadrage EPIC CDX-OCR-BOUNDARY (gouvernance pure, zéro code)

Audit des deux boroughs :

* codex `codex/ocr/` contient la pile IA complète (`LlmOcrEngine`,
  `HttpOllamaChatClient`, `OllamaChatClient`, `OcrPipeline` fallback
  LLM→Tesseract, `OllamaProbe`) — violation de la règle.
* codebase dépend de l'artefact codex (`codebase-plugin/build.gradle.kts:49`
  `implementation(libs.codex.plugin)`) — inversion N1→N2.
* `CodexOcrEngineAdapter` (codebase koog.llm) expose le moteur pur codex
  comme `VisionProvider` — codebase actionne du software OCR.
* `OcrTask` codebase importe `codex.ocr.TesseractOcrEngine`.
* Duplication moteurs vision : `LlmOcrEngine` vs `VisionProvider`
  Gemini/Ollama codebase.
* Pattern hub déjà généralisé ailleurs (PLN-LLM-HUB S-072, SLD-8 US-8.1,
  CAP-ARCH-1) — codex est le dernier N2 hors hub.

12 décisions architecturales (doc `CADRAGE_EPIC_CDX_OCR_BOUNDARY.adoc`) :

. Port = fun interface `codex.ocr.OcrEngine` existante (pas de nouveau type).
. Injection dans `OcrPipeline`/`CollectOcrTask` ; défaut sans injection =
  Tesseract seul (dégradé fonctionnel, backward compat).
. Adapter `VisionOcrEngineAdapter : codex.ocr.OcrEngine` côté codebase
  (wrappe `VisionProvider`) — zéro cycle N2↔N1 (interdit formel).
. Purge pile IA codex : `LlmOcrEngine`, `HttpOllamaChatClient`,
  `OllamaChatClient`. `OllamaProbe` conservé (utilitaire tests assumeTrue).
. Suppression `CodexOcrEngineAdapter` + retrait import Tesseract de
  `OcrTask` (codebase devient IA-uniquement).
. Split-brain `CodexVectorStore` (5 fichiers koog codebase, N1→N2)
  HORS SCOPE — EPIC futur dédié.
. Parité comportementale via characterization tests avant suppression.
. English only, baby-step DDD/TDD/BDD strict.

Découpage : CDX-OCR-0 cadrage (✅ S-096) → CDX-OCR-1 port+characterization
