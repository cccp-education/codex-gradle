== Décisions architecturales

. *Sérialisation rétroactive* : `OntologyMapping` + 3 sous-types
  annotés `@Serializable` pour permettre l'écriture JSON par la tâche.
  Modification additive — les data classes existantes restent
  structurellement inchangées (pas de nouveau champ, pas de nouveau
  constructeur). Le plugin kotlin-serialization est déjà appliqué
  (build.gradle.kts `kotlin-serialization` alias).

. *IO contract* : `sqlFile` (`@InputFile` PathSensitivity.RELATIVE) +
  `jsonFile` (`@InputFile` PathSensitivity.RELATIVE) + `outputFile`
  (`@OutputFile`). Mirror pattern `ImportBookSqlTask` (jsonFile→sqlFile)
  et `AsciiDocToJsonLddTask` (adocFile→jsonFile). Default output
  `build/codex/ontology-mapping.json` (convention `build/codex/`).

. *Groupe `transform`* : aligné sur la taxonomie EPIC K (4 verbes
  GENERER/COLLECTER/TRANSFORMER/DÉPLOYER). `deriveOntology` est un
  transform (SQL LMD → ontology mapping), pas un collect (pas
  d'acquisition de document source).

. *Pas de nouvelle dépendance* : kotlinx.serialization déjà présent
  (catalogue `kotlinx-serialization-json`). `OntologyDeriver` objet pur
  existant — la tâche est un thin wrapper Gradle autour du domaine.
