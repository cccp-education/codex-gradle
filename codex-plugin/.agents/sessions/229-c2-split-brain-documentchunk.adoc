== Objectif

Mission du PROMPT_REPRISE S-229 : **C-2** — supprimer le split-brain
`DocumentChunk`. Deux data classes identiques coexistaient :
`codex.tasks.DocumentChunk` (`ChunkDocumentTask.kt:34`, producteur N2) et
`codebase.store.DocumentChunk` (`DocumentChunk.kt:23`, type N1, migration
verbatim RAG-1). Le producteur codex doit **consommer** le type N1 — pattern
RAG-3 (codex dépend déjà de `libs.codebase.plugin`). Sans cette unification,
le champ `pages` de A-1 serait maintenu dans deux types (prérequis
structurel acté S-227).

== Contexte — pourquoi C-2 existe

C-2 est un **prérequis de A-1** (CB-PAGE-PROVENANCE US-1) : l'EPIC A ajoute
`pages: List<Int>` au type N1 `codebase.store.DocumentChunk`. Si le doublon
`codex.tasks.DocumentChunk` subsiste, le champ serait à maintenir **deux
fois** — exactement le drift que C-2 élimine. Le type N1 est déjà le type
réellement porté sur le classpath : `CodexIngestTask` décode **déjà** dans
`codebase.store.DocumentChunk` (`ignoreUnknownKeys = true`, S-219).
