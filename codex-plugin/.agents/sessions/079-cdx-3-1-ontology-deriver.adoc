== Objectif

Démarrer *CDX-3-1* — premier domaine DDD nouveau du P1 corpus
enrichment : `codex.ontology` + `OntologyDeriver` object pur. L'objectif
est de *calculer* (pas deviner) la cartographie ontologique du corpus
livresque à partir du SQL LMD généré par `ImportBookSqlTask`.

3 requêtes archétypales (P1-19 spec) :
. Bounded contexts  : groupements de tables liées par FK (connectivité).
. Aggregates        : tables racines référencées via ON DELETE CASCADE
                      + leurs entités dépendantes.
. Value objects     : tables sans FK sortantes (pas de REFERENCES dans
                      leur CREATE TABLE body).

== Livrables

=== Domaine `codex.ontology` (12e domaine codex)

* `OntologyMapping.kt` (nouveau, 54 lignes) — 4 data classes immutables :
  - `OntologyMapping(boundedContexts, aggregates, valueObjects)` —
    résultat global de la dérivation.
  - `BoundedContext(name, tables)` — composante connexe du graphe FK.
  - `Aggregate(rootTable, dependentTables)` — table racine + dépendantes
    via CASCADE.
  - `ValueObject(table, columns)` — table sans FK sortantes + ses
    colonnes.

* `OntologyDeriver.kt` (nouveau, 169 lignes) — object pur déterministe :
  - `derive(lddNodes, sqlScript): OntologyMapping` — point d'entrée.
  - `parseTables(sql)` — extrait tables + colonnes via regex DDL
    (`CREATE TABLE IF NOT EXISTS`).
  - `parseOutgoingFks(sql)` — extrait FK sortantes par table
    (`REFERENCES target`).
  - `parseCascadeRoots(sql)` — extrait edges CASCADE (exclut self-ref
    `documents.parent_id → documents`).
  - `computeBoundedContexts` — BFS sur graphe d'adjacence FK (connectivité
    bidirectionnelle), nommage depuis LDD title ou fallback `bc_N`.
  - `computeAggregates` — regroupe CASCADE edges par table racine,
    dependants triés.
  - `computeValueObjects` — tables sans entrée dans `outgoingFks`.

* `OntologyDeriverTest.kt` (nouveau, 13 unit) — couverture exhaustive :
  - empty sql/nodes → empty mapping
  - extraction noms de tables depuis CREATE TABLE
  - bounded context groupe les tables FK-connectées (1 BC pour 3 tables)
  - bounded contexts sépare les groupes déconnectés (2 BCs)
  - aggregates identifie les tables racines CASCADE (book, documents)
  - aggregates collecte les dépendantes (documents→book, paragraphs→documents)
  - aggregates exclut FK sans ON DELETE CASCADE
  - value objects identifie tables sans FK sortantes (book)
  - value objects exclut tables avec REFERENCES (documents, paragraphs)
  - value objects collecte les colonnes du CREATE TABLE body
  - OntologyMapping expose les 3 vues (1 BC + 2 agg + 1 VO)
  - derive est pur/déterministe (same input → same output)
  - derive utilise lddNodes pour nommer le bounded context

== Décisions architecturales

. *Object pur* (pattern `OcrPipeline`/`LicenseZoneDetector`) — pas de
  tâche Gradle dans cette US, `OntologyDeriver` est testable isolément.
  Tâche `deriveOntology` (groupe transform) = US-CDX-3-2 ultérieure.
. *Parsing SQL par regex* — le format DDL généré par `ImportBookSqlTask`
  est déterministe et régulier. Regex `CREATE TABLE` + `REFERENCES` +
  `ON DELETE CASCADE` suffit. Pas de parser SQL complet (overkill).
. *Self-ref exclue des aggregates* — `documents.parent_id → documents`
  est une FK CASCADE mais une table ne peut pas être sa propre dépendante.
  Filtrage `if (fromTable != toTable)`.
. *Bounded context naming* — utilise `lddNodes.first { level > 0 }.title`
  (titre du livre) si disponible, fallback `bc_N`. Permet de nommer
  humainement le context depuis le LDD.
. *Value objects = tables sans FK sortantes* — définition simplifiée
  (P1-19 spec). La notion "colonnes immutables" est une heuristique
  ultérieure (CDX-3-2 ou affinage). Pour l'instant : pas de REFERENCES
  dans le CREATE TABLE body → value object.
