== Décision pilote

Le pilote a tranché l'ordonnancement des trois options en attente du
PROMPT_REPRISE S-227 :

----
Option C (maintenance)  →  Option A (EPIC CB-PAGE-PROVENANCE)  →  Option B (publication)
----

Contraintes actées :

. *Séquence stricte* : C **puis** A **puis** B. B ne commence qu'après
  clôture complète de A (le contenu à publier en B est produit par A).
. *Budget en sessions* : chaque option est « au moins 3 à 4 sessions
  différentes ». Un EPIC de 5 US (A) ne se bâcle pas dans une session ;
  une maintenance (C) est un bloc, pas un one-shot.
. *Aucun chevauchement* : une session exécute une seule option. La
  session 228 ouvre C-1. Le backlog acte les numéros de session.

=== C-2 (S-229) — Split-brain `DocumentChunk` (prérequis de A-1)

*Constat* : deux data classes `DocumentChunk` identiques coexistent —
`codex.tasks.DocumentChunk` (`ChunkDocumentTask.kt:34`, producteur) et
`codebase.store.DocumentChunk` (`DocumentChunk.kt:23`, type N1, migration
verbatim RAG-1). `CodexIngestTask` décode déjà dans le type N1 ; les autres
tasks codex (`SemanticChunker`, `ChunkDocumentTask`, `ExportKnowledgeBaseTask`,
`CollectPageProvenanceTask`, `EnrichJsonLddTask`, `JsonLddEnricher`,
`PageProvenanceResolver`) utilisent le type producteur.

*Travail* (baby-step DDD/TDD/BDD) :

. Décision de cadrage : le type de store vit en N1 (`codebase.store`),
   le producteur codex **consomme** le type N1 — pattern RAG-3 (codex
   dépend déjà de `libs.codebase.plugin`). Alternative écartée sauf raison :
   garder le doublon (double maintenance du futur `pages`).
. Suppression du type `codex.tasks.DocumentChunk` + bascule des 7 fichiers
   prod (imports) vers `codebase.store.DocumentChunk`.
. Characterization tests avant bascule (contrat JSON `chunks.json`
   byte-compatible — `@Serializable` identique).
. Non-régression : `@provenance` (8 scénarios), corpus enrichment,
   `CodexIngestDoubtTest`, `CodexIngestRetrieveIT`.
. Gate : `check` VERT, zéro régression, backward compat JSON totale.

*Valeur* : **débloque A-1** (un seul type porte `pages`), supprime un drift
structurel documenté depuis S-223.

*Risque* : `codex.tasks.DocumentChunk` est référencé par 8 fichiers de test
— migration mécanique, gate par suite complète.

=== C-4 (S-231) — Pollution TOC du chunking + clôture C

*Constat* : le run corpus FPA (S-216) a produit **99 chunks TOC pollués**
(dot leaders `.......` et entrées de table des matières) sur 387. Le bruit
pollue le retrieval (chunks « table des matières » remontent en similarité).

*Travail* (baby-step TDD) :

. `SemanticChunker` / heuristique : détecter et exclure (ou marquer) les
   sections de type TOC — ratio de dot leaders, densité de lignes sans
   phrase, longueur de titre vs contenu.
. Décision d'exposition : exclure au chunking (re-chunk = re-vectorisation
   → coût ONNX local, Loi de l'Économie d'Encre à peser) **ou** marquer
   `doubtful` (déjà transporté N1, zéro re-vectorisation).
. Characterization sur le corpus FPA réel (387 chunks, plancher de
   pollution mesuré).
. BDD `@toc-noise` (runner dédié ou extension d'un runner existant).
. *Clôture C* : audit de sortie — dettes restantes, go/no-go A.

*Alternative si le pilote préfère* : reporter C-4 (cause racine amont

== Méthode (invariante de toutes les sessions)

. *Baby-step DDD/TDD/BDD strict* — RED → GREEN → REFACTOR, 3 niveaux
  (unit → fonctionnel TestKit/ProjectBuilder/testcontainers → Cucumber).
. *English only* sur le code, les features Gherkin, les commentaires et
  les messages de commit.
. *Loi de l'Économie d'Encre* — jamais de re-vectorisation inutile ; delta
  seulement ; base jetable pour les runs de backfill (Règle 2).
. *Cross-borough* : C-2/C-3 (N1 Queens), A-1/A-3 (Queens), A-2 (Brooklyn),
  B-1 (MEMPHIS + Queens), B-2 (Brooklyn) — respecter l'ordre DAG.
. *Gates* : `check` VERT (Kover + validatePlugins) avant toute clôture ;
  commit/push en fin de session (décision pilote 2026-09-17) ; publication
  **uniquement** sur accord pilote.
. *Piège transverse* : mavenLocal est **partagé** entre boroughs — une
  session parallèle peut réécrire un jar en cours de `check` (course S-226
  `CodexIngestRetrieveIT`) ; vérifier par stash avant d'accuser le diff.
