:description: Cadrage de l'EPIC CB-STORE-UNIFY (consolidation des deux stores vectoriels côté codebase)

== Source
décision archi S-097 (consolidation JDBC legacy HORS SCOPE de CDX-RAG-SOCLE, reportée à un EPIC futur dédié).

== Pattern
gouvernance pure puis baby-step TDD — à cadrer.

== Contexte
Après la migration `RagVectorStore` (RAG-1→4) vers `codebase.store`,
deux stores coexisteront côté codebase :

. `codebase.store.RagVectorStore` (R2DBC, migré verbatim depuis
   `codex.store.CodexVectorStore` — socle canonique, tables pgvector
   `codex_documents`/`codex_chunks` inchangées).
. `codebase.rag.VectorStore` (JDBC legacy, schéma `code-index`,
   `initSchema` DROP CASCADE destructif — ancêtre P0 précédant la
   montée de codebase N1).

Le store JDBC legacy est un risque technique : DROP CASCADE destructif,
schéma divergent, double surface de maintenance. L'EPIC CB-STORE-UNIFY
consolide les deux en supprimant le store JDBC legacy après migration
des éventuels consommateurs résiduels vers `RagVectorStore`.

== Décisions clés
. Le store `codebase.rag.VectorStore` sera supprimé après migration de ses consommateurs vers `codebase.store.RagVectorStore`.
. La migration consistera à remplacer les appels à `codebase.rag.VectorStore` par `codebase.store.RagVectorStore` (API identique `searchBlocking`).
. Les tests de caractérisation seront effectués pour s'assurer de la compatibilité.
. Un gate de non-régression sera appliqué après la suppression.
. Les scénarios Cucumber BDD seront rédigés pour valider le fonctionnement du store unifié.
