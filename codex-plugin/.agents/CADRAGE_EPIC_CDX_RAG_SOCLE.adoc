== Contexte — La règle du pilote

Le pilote acte (session 097) : *le RAG est un élément du contexte augmenté,
donc le RAG se fait dans codebase* (Queens N1). La gouvernance racine
l'écrit déjà (« Queens fournit le RAG socle pgvector aux N2 ») mais le code
n'a jamais suivi. Ce document cadre l'EPIC de migration.

== Décisions architecturales (cadrage S-097)

. *EPIC cross-borough* Brooklyn (codex) + Queens (codebase). Priorité P1.
Exécution *après* CDX-OCR-BOUNDARY (gate : US-2 OCR terminée avant RAG-4 —
sinon codebase garde des imports `codex.ocr.*` et ne peut pas retirer la
dépendance).

. *Nouveau domaine `codebase.store`* côté socle — `RagVectorStore` (nom neutre)
reprend la logique verbatim de `CodexVectorStore` : factory R2DBC, embedding
ONNX AllMiniLmL6V2, `searchBlocking`/`search`. Même API, autre domicile.

. *Les templates SQL migrent avec le store* — `IngestStatements` (DDL/UPSERT
tables `codex_*`) devient propriété du socle : c'est lui qui possède l'accès
schéma. Les tâches codex orchestrent (lire fichiers, chunker, appeler le
socle) — thin wrappers, pattern PLN-LLM-HUB.

. *Tables pgvector INCHANGÉES* — `codex_documents`/`codex_chunks` gardent leur
nom (backward compat total, zéro migration de données, zéro re-vectorisation).
La convention de nommage historique reste ; le socle documente que ces tables
hébergent le corpus documentaire codex.

. *codex dépend de codebase* — `implementation(libs.codebase.plugin)` ajouté
côté codex. Pattern établi : planner/slider/capsule consomment déjà le socle
N1 ainsi. Simultanément *codebase retire `libs.codex.plugin`* → zéro cycle
(l'interdit formel N2↔N1 cyclique est respecté : flèche unique N2→N1).

. *Contrat N0 MEMPHIS rejeté pour cette itération* — le store est un service
implémenté (R2DBC+ONNX), pas des types purs. Le pattern LlmBuildService
(dépendance directe au socle) fait foi. Un contrat N0 pourra être extrait
plus tard si un 3e consommateur apparaît.

. *Consolidation `codebase.rag.VectorStore` (JDBC legacy) HORS SCOPE* —
c'est l'indexeur code-index interne de Queens, distinct du corpus
documentaire. Sa fusion avec `RagVectorStore` est candidate à un EPIC futur
(CB-STORE-UNIFY). Son `initSchema` destructif (DROP CASCADE) est signalé
comme smell à ne PAS reproduire dans le nouveau domaine.

. *`codex.profile.PgVectorSessionMemory` inchangé* — session memory ≠ corpus
RAG (décision RC-04 S-076 réaffirmée). Seul le KDoc mentionnant
« pattern CodexVectorStore » sera actualisé.

. *Non-régression runner-gradle (N3)* — `assembleCompositeContext` consomme
les contrats N0 (contexts-contracts) déjà stables ; zéro impact attendu.
Vérification gate en clôture de RAG-3.

. *English only*, baby-step DDD/TDD/BDD strict RED → GREEN → REFACTOR,
3 niveaux (unit → functional → Cucumber).

== Gates et risques

* *Cycle N2↔N1* : impossible par construction — RAG-4 est gated par RAG-3,
lui-même gated par OCR-1/OCR-2. Vérification mécanique (`rg import codex.`).
* *Qualité de recherche* : logique migrée verbatim + characterization tests
avant suppression → zéro changement comportemental attendu.
* *Consommateurs indirects* : training (TRN-5) passe par runner-gradle
(`assembleCompositeContext`) — aucun impact tant que les contrats N0 sont
stables.
